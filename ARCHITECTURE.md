# AEL Design System — Architecture

**How the system is architected.**

---

## Vision

An enterprise-grade, vendor-neutral, cross-platform Design System that can be implemented consistently across development frameworks and design tools while preserving governance, traceability, scalability, and long-term maintainability.

## 7-Layer Architecture

```
G — Governance       Policy    →  Rules and constraints
I — Infrastructure   Engine    →  Build, validation, registry
F — Foundations      Primitives → Tokens, assets, component model
C — Components       Blocks    →  37 reusable UI components
P — Composition      Assemblies → Layouts, navigation, templates
D — Distribution     Delivery  →  11 platform targets
K — Knowledge        Adoption  →  Documentation, playground, guides
```

## SSOT Architecture

All concrete design values live exclusively in `06-Implementation/tokens/` (17 JSON files, 143 tokens). Standards define rules only. Specifications declare token bindings only. No value is duplicated across layers. The build pipeline validates this invariant at every build.

```
Standards (rules) → Specifications (token ID refs) → Implementation (SSOT values) → Registry (generated index)
```

```
06-Implementation/tokens/

```

## Data Flow

```
Design Tokens (SSOT)
    ├──→ Platform CSS (var(--ael-*))
    ├──→ Platform SCSS ($...)
    ├──→ Platform Swift (AELTokens.xxx)
    ├──→ Platform Android (R.color.ael_xxx)
    ├──→ Platform Figma (figma-tokens.json)
    ├──→ Platform W3C (design-tokens.json)
    └──→ Platform JSON (tokens.json)

Component CSS
    └── consumes var(--ael-*) references (zero hardcoded values)

Asset SVGs
    └── referenced by components via AS-icon-* IDs
```

## Registry Architecture

Three generated registries, never hand-authored:

| Registry | Source | Contents |
|----------|--------|----------|
| `token-registry.json` | `06-Implementation/tokens/` | 143 tokens, 15 categories |
| `asset-registry.json` | `06-Implementation/assets/` | 18 assets (15 icons, 3 logos) |
| `component-registry.json` | `06-Implementation/Components/` | 37 components, 7 groups |

All regenerated by `node 09-Build/build.js`.

## Governance Model

```
AEL Meta-Architecture
  → Ontology
    → Constitution
      → Operational Laws (Dependency Hierarchy, Naming Convention, Override Policy)
        → Standards (rules only)
          → Specifications (token ID refs only)
            → Implementation (SSOT)
              → Registry (generated)
```

Authority flows top-down. Implementation may not override Specification. Specification may not override Standard.

## Project Identity

The official visual identity of the AEL Design System is defined by assets in `06-Implementation/assets/logos/`. The canonical logo is `ael-logo.svg`. All documentation, websites, playgrounds, and platform libraries must use this logo without modification. See [BRAND.md](./BRAND.md).
